# 交大科创生存手册（SJTU STI Wiki）

## 核心问题

当你想接触科研、参加创赛或验证一个创业想法时，怎样找到可信信息并完成下一步，而不是继续被焦虑和信息差困住？

## 这是什么

> [!info] 事实
> 本 Wiki 由校团委科创协会建设，[GitHub](https://github.com/RRRealCedric/SJTU-STI-Wiki) 是公开平台与贡献入口，微信推送同步分发。公开内容须经科协老师批准。

我们不只记录论文、奖项或融资结果，更关注过程：第一封邮件怎样写，第一个任务怎样跑通，队伍为什么内耗，需求为什么没有人愿意使用，以及什么时候应该停止。

“交大科创棱镜”是本 Wiki 的访谈与内容栏目。访谈原始材料仅限科协内部；公开案例和方法必须经过纸质授权、脱敏、核验与审核。

## 三条路径不是等级

| 路径 | 首要目标 | 主要证据 | 常见误区 |
| --- | --- | --- | --- |
| 科研 | 形成可检验的新认识 | 实验、数据、论证、论文或研究记录 | 把进组或署名当成科研本身 |
| 创赛 | 在规则内形成可评审项目 | 项目材料、验证证据、展示与答辩 | 把包装当内容，把奖项当市场 |
| 创业 | 为真实用户持续创造并交换价值 | 使用、付费、留存、交付与现金流 | 把技术先进或导师认可当需求成立 |

同一项目可以在三条路径之间转换，但评价标准不会自动相同。科研成果转为创赛项目，需要重新组织评审证据；创赛项目转为创业，需要重新验证用户和交易。

## 如何判断信息

每篇内容尽量区分：

- **事实**：有官方或可核验来源，并记录核验日期。
- **经验**：来自特定当事人的经历，保留背景与局限。
- **编辑建议**：基于资料和案例提出的行动建议，不宣称唯一正确。

具体标准见 [[SJTU STI Wiki 内容模型与编辑规范]]。

## 如何参与

- 在 GitHub Issue 提交问题、错误、失效入口或选题建议。
- 通过 Pull Request 补充来源、方法、模板和已获授权的案例。
- 不要把原始访谈、私人联系方式或未公开材料提交到公开仓库。
- 所有公开合并须完成编辑检查并取得科协老师批准。

> GitHub Issue 已作为公开纠错入口；首批维护人名单仍待项目组补充。
