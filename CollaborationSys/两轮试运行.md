# 两轮试运行

前两场访谈用来验证流程和工时。先在 `Sources` 建立知识缺口与 `INT` 编号，再邀请嘉宾。人选、联系方式、授权和原始材料仅在受控空间处理。

## 第一轮

| 环节 | 分工 | 交付 |
| --- | --- | --- |
| 访谈 | 成员 A 主访，B 记录 | 简报、提纲、纸质授权编号与内部记录 |
| 拆卡 | A、B 分别处理访谈的不同时间段 | `RAW` 卡，保留时间点与语境 |
| 复核 | 成员 C | 忠实性、适用条件和敏感信息检查 |
| 建节点 | 成员 D | 支持卡、反例、局限和候选页面 |
| 页面编辑 | 相关 Page Owner | 一条具体修改进入 Publish Queue |
| 观察 | 主编 | 记录耗时、重复字段和争议点 |

## 第二轮

由 C、D 负责访谈，其他成员轮换拆卡、复核、建节点和页面编辑。只在前一轮的问题得到修正后开始；成员字母在启动会上对应实际姓名和责任，但不要把真实身份填进公开模板。

## 复盘问题

- 每场访谈形成多少张可复核卡，哪些卡缺少语境或适用条件？
- `RAW → REVIEWED`、`REVIEWED → CLUSTERED` 分别花了多久？
- 争议来自事实冲突、适用条件不同，还是页面范围不清？
- `UNPLACED` 是否过多？若过多，先修订页面词表。
- 哪些节点真正补足了 Wiki 的内容缺口？
- 双人复核和老师批准记录是否可追溯？

两轮后由主编修订字段和角色安排，再决定每学期 3–5 位嘉宾的实际产能。
