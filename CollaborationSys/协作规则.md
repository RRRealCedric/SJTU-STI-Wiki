# 协作规则

## 一条内容如何流转

| 环节 | 输入 | 责任角色 | 交付与放行条件 |
| --- | --- | --- | --- |
| 定义问题 | 学生问题、页面缺口、过期资料 | 主编、选题编辑 | `Sources` 有知识缺口与采访必要性 |
| 采集来源 | 访谈简报、提纲、纸质授权 | 访谈负责人、记录人 | 原始资料进入受控资料库，`Sources` 记录代号和授权编号 |
| 拆经验卡 | 逐字稿或访谈记录 | Extractor | `Cards` 保留陈述、语境、适用条件和时间点 |
| 复核卡片 | `RAW` 卡片 | 非原提取人 | 语义忠实、隐私标记和类型检查后设为 `REVIEWED` |
| 建知识节点 | 已复核卡片 | Node Editor | 列明支持卡、反例、适用范围和证据局限 |
| 编辑页面 | 可使用的节点、页面范围 | Page Owner | `Publish Queue` 有目标页面、具体修改和审稿人 |
| 公开发布 | Wiki 草稿、核验和审查记录 | 审稿人、科协老师 | 老师批准后合并 PR，记录链接和复审日期 |

## 角色边界

一个成员可以兼任多个角色，但争议内容不得只由同一人提取、审查并批准。页面由一名 Page Owner 维护最终结构，其他成员通过节点和发布队列贡献材料。

| 角色 | 可以做 | 交给下一角色的内容 |
| --- | --- | --- |
| Extractor | 按原语境制作经验卡，标注待核验信息 | `RAW` 卡片，不替嘉宾写普遍结论 |
| Card Reviewer | 检查陈述、语境、适用条件及识别风险 | `REVIEWED` 或 `HOLD` 卡片 |
| Node Editor | 比较多张卡与反例，写条件化命题 | 节点草稿，不改写卡片原意 |
| Page Owner | 决定页面位置、措辞和相邻链接 | 页面草稿与发布队列记录 |
| Editor-in-Chief | 处理跨页面冲突、未归类卡片和优先级 | 明确页面责任人与审查安排 |
| 科协老师 | 批准公开 GitHub 内容，负责微信、视频和线下发布 | 明确批准记录及渠道范围 |

## 固定节奏

- 每周一次短会，只看 `Publish Queue`：下一步、责任人、阻塞、预计提交时间。
- 每两周处理 `UNPLACED` 和 `NEW_PAGE`，决定保留、转页或新建槽位。
- 每学期开始时整理高频问题和页面缺口；学期末复盘复审逾期、卡片利用率和内容质量。
- 同一页面的多人修改先由 Page Owner 合并成一个草稿，避免并行改写造成冲突。

## 发布交接

每个 PR 应说明：目标页面、使用的知识节点、可公开的来源类型、事实核验情况、适用条件、隐私审查结果、审稿人和老师批准记录。内部 ID 可以写在受控审稿单；公开 PR 不包含访谈原文、录音时间戳、嘉宾身份或内部资料链接。

没有纸质授权、无法脱敏、制度信息缺少官方核验，或老师尚未批准时，发布队列停在 `HOLD` / `REVIEW`，不合并。
