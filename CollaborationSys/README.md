# SJTU STI Wiki 协作系统

本目录提供八人编辑团队的工作约定和空白模板。实际访谈资料与工作总表属于科协内部材料，不通过公开 GitHub 仓库协作。

## 从哪里开始

1. 主编阅读[协作规则](./协作规则.md)，指定第一轮角色和每个页面的负责人。
2. 团队共同确认[字段与状态](./字段与状态.md)，在受控共享盘中保留一份五工作表总表。不要让八个人各自维护副本。
3. 页面负责人核对[页面槽位与现有页面](./页面槽位与现有页面.md)，补齐工作表 `Pages` 中的负责人和范围。
4. 第一次访谈前复制[访谈简报](./模板/访谈简报.md)和[访谈提纲](./模板/访谈提纲.md)。
5. 按[两轮试运行](./两轮试运行.md)开始工作，复盘后再调整分工。

## 文件地图

| 文件 | 用途 | 存放边界 |

| `协作规则.md` | 角色、交接、会议和发布责任 | 可在仓库维护；不自动进入网站 |

| `模板/*.md` | 访谈、卡片、节点、页面和审查的空白模板 | 可在仓库维护；填写后的副本留在内部 |
| `private/后台协作总表.xlsx` | Sources、Cards、Nodes、Pages、Publish Queue | 本地起始副本；被 Git 忽略，迁入受控共享盘后以共享盘版本为准 |

## 四层关系

`INT-001` 来源 → `E-001-01` 经验卡 → `K-R-001` 知识节点 → `R4` 页面槽位。

一条经验卡保留受访情境和适用条件。知识节点比较多个来源及反例。页面负责人再决定如何写成可公开的 Wiki 段落。案例 `CASE-001` 是多张卡片形成的过程叙事，不是卡片类型。

## 公开边界

- `private/`、访谈录音、逐字稿、纸质授权扫描件、联系人和未脱敏卡片不进入公开仓库、网站或公开 Issue/PR。
- 总表中的 `Source ID`、`Card ID` 和 `Node ID` 用于内部追溯。公开 PR 只写通过审查且可以披露的来源说明，不粘贴内部材料或受限链接。
- GitHub 负责已批准内容的版本审查与网站发布；所有公开发布须经科协老师批准。微信、视频与线下活动由老师负责。
- 本目录的文档即使不生成网站页面，只要提交到当前公开仓库，仍可在 GitHub 查看；内部记录始终放在 `private/` 或受控共享盘。
